2018 Q1 – Schema Refinement 15 marks
Given
R(A, B, C, D)  ·  F = { AB→C, C→D, D→B }
a
Find all the nontrivial FDs that follow from F. Consider only FDs with a single attribute on the right side.
3 marks
Answer

Use transitivity and augmentation on the given FDs to derive all implied FDs:

// Given: AB → C C → D D → B // Apply Transitivity: AB→C, C→D implies AB → D // Apply Transitivity: AB→D, D→B implies AB → B // trivial (B is in LHS) — skip // Apply Transitivity: C→D, D→B implies C → B // Apply Transitivity: AB→C, C→B implies (already have AB→B trivial) // Also: AB→B is trivial; AB→A is trivial — skip all trivial // Apply: D→B already given. AC→? : AC→C (trivial), with C→D gives AC→D AC → D // by augmentation (A added to C→D) AC → B // by transitivity: AC→D, D→B // AD→? : AD→D (trivial), with D→B gives AD→B AD → B // by augmentation (A added to D→B)
All nontrivial derived FDs (single RHS)
AB→C, AB→D, C→D, C→B, D→B, AC→D, AC→B, AD→B (and augmented variants)
b
Find all the keys that follow from the given FDs, showing how you found them.
2 marks
Answer

Compute the attribute closure for candidate sets. A set X is a key if X⁺ = {A,B,C,D} and no proper subset also gives all attributes.

// Try single attributes: {A}⁺: only A (no FD has just A on LHS) = {A} ✗ not a key {B}⁺: only B = {B} ✗ not a key {C}⁺: C→D, D→B → {C,D,B} = {C,D,B} ✗ missing A {D}⁺: D→B → {D,B} = {D,B} ✗ not a key // Try pairs: {A,B}⁺: AB→C → {A,B,C}, C→D → {A,B,C,D} = ALL ✓ superkey! Is any subset a key? {A}⁺ = {A} ✗, {B}⁺ = {B} ✗ → AB is a CANDIDATE KEY {A,C}⁺: AC→D (from C→D+augment) → {A,C,D}, D→B → {A,C,D,B} = ALL ✓ superkey! Is any subset a key? {A}⁺={A}✗, {C}⁺={C,D,B}✗ (missing A) → AC is a CANDIDATE KEY {A,D}⁺: D→B → {A,D,B}, no more... = {A,D,B} ✗ missing C
Candidate Keys
AB and AC are the only candidate keys.
c
Is R in 3NF? Give reasons for your conclusion.
2 marks
Answer

Prime attributes (in any candidate key AB or AC): A, B, C
Nonprime attributes: D only

// 3NF check: for every FD X→Y where Y is nonprime, X must be a superkey OR Y is prime AB → C : C is prime ✓ C → D : C is not a superkey. D is nonprime. → Check: is C a superkey? {C}⁺ = {C,D,B} ≠ all attrs. NO. // BUT in 3NF, we allow X→A if X is superkey OR A is prime // D is nonprime, C is not a superkey → VIOLATION of 3NF? Let's verify... D → B : B is prime ✓ (B is in candidate key AB)
Conclusion
R is in 3NF. For C→D: although C is not a superkey, we must check if this violates 3NF. D is a nonprime attribute and C is not a superkey — this IS a violation. R is NOT in 3NF because C→D exists where C is not a superkey and D is nonprime.
d
Is R in BCNF? If not, convert it to BCNF.
3 marks
Answer

BCNF rule: For every nontrivial FD X→Y, X must be a superkey.

// Candidate keys: AB, AC. Superkeys include AB, AC, ABC, ABD, ACD, ABCD etc. AB → C : AB is a superkey ✓ C → D : C is NOT a superkey ✗ BCNF VIOLATION D → B : D is NOT a superkey ✗ BCNF VIOLATION // Decompose for C→D (the first violation): // Rule: decompose R into (R - Y) and (XY) // R = ABCD, X=C, Y=D R1 = R - {D} = ABC (retains FD AB→C) R2 = {C,D} = CD (retains FD C→D) // Check R1(A,B,C): FDs that apply: AB→C. Is AB a superkey of R1? {A,B,C} = all of R1 ✓ BCNF // Check R2(C,D): FDs that apply: C→D. Is C a superkey of R2? {C,D} = all of R2 ✓ BCNF // Note: D→B is lost in this decomposition (not dependency-preserving)
BCNF Decomposition
R1(A, B, C) with FD: AB→C
R2(C, D) with FD: C→D
Both are in BCNF. Note: D→B is not preserved (BCNF does not guarantee dep-preservation).
e
Check whether F = {A→C, AC→D, E→AD, E→H} and G = {A→CD, E→ACH} are equivalent.
5 marks
Answer

To show equivalence, prove F⁺ = G⁺ by showing F covers G AND G covers F.

// ── Prove G is covered by F (compute X⁺ using F for each FD in G) ── {A}⁺ w.r.t. F: Start: {A} A→C: add C → {A,C} AC→D: AC ⊆ closure → add D → {A,C,D} No more. {A}⁺ = {A,C,D} → covers A→CD in G? CD ⊆ {A,C,D} ✓ {E}⁺ w.r.t. F: Start: {E} E→AD: add A,D → {E,A,D} E→H: add H → {E,A,D,H} A→C: add C → {E,A,D,H,C} AC→D: already have D {E}⁺ = {E,A,D,H,C} → covers E→ACH in G? ACH ⊆ {E,A,D,H,C} ✓ // G is covered by F ✓ // ── Prove F is covered by G (compute X⁺ using G for each FD in F) ── {A}⁺ w.r.t. G: Start: {A} A→CD: add C,D → {A,C,D} {A}⁺ = {A,C,D} → covers A→C? C ⊆ {A,C,D} ✓ {A,C}⁺ w.r.t. G: Start: {A,C} A→CD: add D → {A,C,D} {AC}⁺ = {A,C,D} → covers AC→D? D ⊆ {A,C,D} ✓ {E}⁺ w.r.t. G: Start: {E} E→ACH: add A,C,H → {E,A,C,H} A→CD: add D → {E,A,C,H,D} {E}⁺ = {E,A,C,H,D} → covers E→AD? AD ⊆ {E,A,C,H,D} ✓ → covers E→H? H ⊆ {E,A,C,H,D} ✓ // F is covered by G ✓
Conclusion
Since F covers G and G covers F, F and G are equivalent (F⁺ = G⁺). ✓

b
Decompose CUSTOMER into 2NF, then 3NF relations.
4 marks
Answer

Key = N (single attribute). With a single-attribute key, partial dependency is impossible → already in 2NF. Move directly to 3NF.

// Identify transitive dependencies (non-prime → non-prime): // N→RCT (direct) ✓ // N→RCT→Z means N→Z is TRANSITIVE (via RCT) // Z→CT means Z→C and Z→T are transitive dependencies // For 3NF: remove transitive deps by decomposing // FD RCT→Z causes transitivity. Decompose: R1 = CUSTOMER_ZIP(R,C,T, Z) // FD: RCT→Z R2 = CUSTOMER_INFO(N, R, C, T) // FD: N→R, N→C, N→T // Check R1: Is RCT a superkey? {RCT}⁺ = {R,C,T,Z} = all of R1 ✓ // Now Z→CT in R1: Z is not a superkey of R1 → still violates 3NF! // Further decompose R1: R1a = ZIP_LOC(Z, C, T) // FD: Z→CT R1b = CUST_ZIP(R,C,T, Z) → simplify to CUST_ADDR(R,C,T, Z) // But RCT→Z and Z→CT overlap... merge carefully: // Cleaner 3NF decomposition: R1 = (N, R) // N→R R2 = (N, C, T) → but N→CT and Z→CT...
3NF Decomposition
R1: CUSTOMER_BASE(N, R, C, T) — FD: N→RCT
R2: ZIP_INFO(RCT, Z) — FD: RCT→Z
R3: ZIP_LOCATION(Z, C, T) — FD: Z→CT

This removes all transitive dependencies. All three are in 3NF.

Answer

c
What is dependency preservation? Review potential causes for losing it in BCNF. Justify with an example.
4 marks
Answer

Definition: A decomposition of R into relations R1, R2, … is dependency-preserving if every FD in F can be checked by examining only a single Ri (without needing a join). Formally: F⁺ = (F_R1 ∪ F_R2 ∪ …)⁺.

Why BCNF may fail: When we decompose to fix a BCNF violation, the FD that caused the violation gets "split" across two relations, and it can no longer be verified without joining them.

// Classic example: R(C, S, Z) with FDs: CS→Z, Z→C // Candidate keys: CS and ZS (since Z→C, ZS→CS→Z, so ZS gives all) // BCNF check: Z→C — is Z a superkey? {Z}⁺ = {Z,C} ≠ all attrs → VIOLATION // Decompose for Z→C: R1 = (Z, C) // captures Z→C R2 = (Z, S) // to keep remaining attrs // Check: CS→Z — is this FD preserved? // C and S are in different relations (R1 has Z,C; R2 has Z,S) // CS→Z CANNOT be checked in any single relation → NOT preserved! → BCNF decomposition loses the FD CS→Z
Conclusion
BCNF can cause dependency loss when a violating FD's LHS attributes end up split across different decomposed relations. Unlike 3NF, BCNF does not guarantee dependency preservation.

Answer

c
S(A,B,C,D) with FDs: A→BC, B→C, A→B, AB→D, D→A. Is this set minimal? If not, find the minimal set.
7 marks
Answer

The set is NOT minimal — A→BC has a multi-attribute RHS, violating minimality rule 1.

1
Step 1 — Split all RHS to single attributes
A→BC becomes A→B and A→C B→C stays B→C A→B stays A→B // duplicate! Remove one A→B AB→D stays AB→D D→A stays D→A After removing duplicate: { A→B, A→C, B→C, AB→D, D→A }
2
Step 2 — Minimize LHS of AB→D
// Can we remove A from AB→D? Check if D ∈ {B}⁺: {B}⁺ = {B,C} → D ∉ {B}⁺ → A is needed // Can we remove B from AB→D? Check if D ∈ {A}⁺: {A}⁺ = {A,B,C} (using A→B, A→C, B→C) D ∉ {A}⁺ → B is needed // AB→D stays as is
3
Step 3 — Remove redundant FDs
// Check A→C: without A→C, is C ∈ {A}⁺? {A}⁺ without A→C: A→B → {A,B}; B→C → {A,B,C} C ∈ {A,B,C} → A→C is REDUNDANT! Remove it. Current set: { A→B, B→C, AB→D, D→A } // Check A→B: without A→B, is B ∈ {A}⁺? {A}⁺ without A→B: only D→A applies if A in closure... No FD fires with just A. {A}⁺ = {A} B ∉ {A} → KEEP A→B // Check B→C: without B→C, is C ∈ {B}⁺? {B}⁺ = {B} → C ∉ {B} → KEEP B→C // Check AB→D: without AB→D, is D ∈ {A,B}⁺? {A,B}⁺ = {A,B,C} (via A→B, B→C) D ∉ {A,B,C} → KEEP AB→D // Check D→A: without D→A, is A ∈ {D}⁺? {D}⁺ = {D} → A ∉ {D} → KEEP D→A
Minimal Cover
G = { A→B, B→C, AB→D, D→A }

The redundant FD A→C was removed because it is implied by A→B and B→C (transitivity).
